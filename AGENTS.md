# Karpender Agent Guide

## Project Overview

Karpender is a Rust GTK/libadwaita desktop app for Fedora/Linux that reads a physical microphone through PipeWire, applies voice anonymization DSP, exposes a virtual microphone, and optionally monitors the processed audio to speakers.

Core flow:

```text
physical mic -> PipeWire capture stream -> DSP -> virtual mic queue -> PipeWire virtual source
                                                -> optional monitor queue -> speakers
```

## Important Files

- `src/main.rs`: module entrypoint.
- `src/app.rs`: GTK/libadwaita application bootstrap.
- `src/ui/window.rs`, `src/ui/layout.rs`: main window, controls, settings wiring, Start/Stop.
- `src/window_controller/`: the glue between the widgets and the audio session.
- `src/audio/devices.rs`: input source discovery via `pw-dump`.
- `src/audio/engine.rs`, `src/audio/session.rs`, `src/audio/streams/`: PipeWire streams, virtual mic, optional monitor stream.
- `src/audio/sample_queue.rs`, `src/audio/format.rs`: the lock-free queue between capture and playback, and the buffering limits that set latency.
- `src/config.rs`: JSON settings under XDG config, including `VoiceMode`.
- `src/profiles.rs`: the built-in profiles offered in the UI.

The DSP lives in `src/dsp/`, one concern per file:

- `mod.rs`: shared constants and the module list.
- `params.rs`: the atomic parameter block shared with the UI thread.
- `tracker.rs`: autocorrelation pitch tracker.
- `pitch.rs`: granular pitch shifter. Its grain has to hold an even number of input periods, see `grain_window`.
- `biquad.rs`, `formant.rs`: filter primitives and the spectral envelope remapper.
- `identity.rs`: the per-session random voice identity.
- `recipe.rs`: per mode pitch target, formant ratio, tilt and breath.
- `noise.rs`, `math.rs`: PRNG and small helpers.
- `processor.rs`: the chain itself, `VoiceProcessor::process_sample`.
- `tests.rs`: all DSP tests.

Supporting measurements live in `experiments/`; those scripts are Python and are
not part of the build.

## Commands

- Format: `cargo fmt`
- Format check: `cargo fmt --check`
- Compile check: `cargo check`
- Tests: `cargo test`
- Run app locally: `cargo run`

PipeWire inspection helpers:

- List nodes: `pw-dump --no-colors`
- Compact node view:

```bash
pw-dump --no-colors | jq -r '.[] | select(.type=="PipeWire:Interface:Node") | [.id, .info.props["media.class"], .info.props["node.name"], .info.props["node.description"], .info.state] | @tsv'
```

## Implementation Notes

- Keep audio callback code panic-free. PipeWire callbacks cannot unwind safely; panics can abort the whole process.
- Avoid allocations, blocking locks, and UI calls inside audio callbacks. Existing code uses `try_lock` and channel events.
- Do not let monitor playback consume from the virtual mic queue. It must use a separate queue so apps like Telegram still receive audio.
- Capture routing depends on `"target.object"` and WirePlumber/PipeWire autoconnect. Be careful when changing stream properties.
- DSP controls are currently named by behavior in the UI:
  - `Noise Cleanup`: soft downward expander, not a hard gate.
  - `Privacy Amount`: strength of voice disguise.
  - `Flatten Intonation`: reduces recognizable prosody without replacing speech with a carrier.
- Keep speech intelligibility as a first-class requirement. Prefer moderate pitch/formant/timbre changes over harsh robot/vocoder effects.
- Latency is a feature. Three places control it and all three have tests: the requested PipeWire quantum in `src/audio/streams/mod.rs`, the queue cushion in `src/audio/sample_queue.rs`, and the shifter grain in `src/dsp/pitch.rs`. Do not raise a buffer to paper over an underrun without measuring first.
- The delay line shifter is periodic with its grain, so its output frequency is quantised to `f_in + k / grain`. A grain that is not an even number of input periods therefore returns the wrong pitch, which sounds thin and squeaky. `experiments/pitch_shifter_spectrum.py` demonstrates it.
- `data/icons/com.github.xierongchuan.karpender.svg` is generated by `experiments/app_icon.py`. Edit the script, not the SVG.

## Verification Expectations

For code changes, run at least:

```bash
cargo fmt --check
cargo check
cargo test
```

Manual audio checks should cover:

- selected physical mic raises the level meter;
- `Karpender Privacy Voice Mic` appears as an input source in Telegram/browser apps;
- monitor mode plays processed speech to speakers/headphones;
- Stop releases streams without hanging;
- no feedback loop when monitor mode is used with speakers near the mic.

Use headphones when testing monitor mode.
